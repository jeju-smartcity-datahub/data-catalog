# 데이터카탈로그 구성

## 서비스

| 구성 | 역할 |
| --- | --- |
| `web` | 공개 데이터셋 검색·필터, 메타데이터·필드·레코드 조회, DCAT 다운로드 |
| `admin` | 허브 연결·수집·게시, 분류·표준사전, 계정·기관 및 DCAT 관리 |
| `server` | 공개·관리 API, 권한 검사, 업무 처리, 수집 작업 실행 |
| PostgreSQL | 메타데이터, 게시 버전, 연결·일정·작업 상태, 권한·이력 저장 |
| `edge` | 웹·관리자·API 요청을 같은 접속 주소에서 분기 |

```text
브라우저·외부 시스템 ─ edge ─┬─ web
                            ├─ admin 정적 파일
                            └─ server ─┬─ PostgreSQL
                                       └─ 허브 어댑터 ─ 데이터허브
```

카탈로그는 데이터허브의 메타데이터를 수집하여 검색·게시한다. 데이터허브 제품 자체와 실제 데이터 저장소는 별도 시스템이다.

Compose 서비스는 `db`·`api`·`web`·`edge`로 구성한다. `admin` 빌드 결과는 `edge`에서 제공한다.

## 데이터 처리

1. 관리자 연결 설정과 허용 주소 확인
2. 허브 목록·상세 조회 및 수집 후보 저장
3. 필수 메타정보·분류 확인
4. 선택 게시 또는 연결별 자동 게시
5. 공개 검색·상세와 DCAT 제공

수집 작업의 상태·건수·실패 사유와 예약 정보를 DB에 저장한다. 같은 요청의 중복 실행을 제어하고, 자동 게시에서는 수동 작성 내용과 비공개·철회 자료를 보호한다.

## API 경계

| 경로 | 역할 |
| --- | --- |
| `/api/catalog/v1` | 현재 공개 게시본 검색·상세·DCAT |
| `/api/admin/v1` | 인증된 관리 업무 |
| `/api/docs/v1/datasets/{id}` | 게시 데이터셋의 제공 계약에 따른 API 문서 상태 |

- 허브 연계: KETI 데이터셋 목록·상세, 참조 데이터모델 조회. NGSI-LD 허브는 별도 어댑터 사용
- 외부 메타데이터 제공: DCAT의 JSON-LD·Turtle
- JSON-LD 응답 형식과 NGSI-LD API 규격은 별도
- 데이터 미리보기는 현재 게시본에 공개 필드와 유효한 조회 연결이 있을 때 제공한다. KETI는 수집 이력과 허브 데이터셋 ID를 이용해 엔티티를 조회한다. 메타데이터와 엔티티 서버의 주소는 별도로 지정할 수 있다.

## 권한과 저장

- 서버에서 로그인·역할·기관·객체 범위 검사
- 변경 요청의 CSRF·버전·중복 요청 검사
- 초안과 공개 게시본 분리, 게시 버전 보존
- 비밀값과 운영 설정은 공개 코드·브라우저 응답에서 제외
- DB 변경은 순서 있는 Flyway migration으로 적용

## 개발 구성

- 공개 웹: Next.js·React·TypeScript
- 관리자 웹: Vite·React·TypeScript
- 서버: Java 21·eGovFrame 5·Spring Boot
- 저장소: PostgreSQL 17
- 배포: Docker Compose

의존성의 정확한 버전은 각 프로젝트의 잠금 파일·`pom.xml`과 `sbom/`에 기록한다.
